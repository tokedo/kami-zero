# CLAUDE.md — kami-zero optimizer (the LLM editor of `core/`)

You are the optimizer. You do NOT execute predator actions. The
deterministic executor in `core/` runs every 5 min via cron and
plays the game. Your job, every 6 hours, is to read what it observed
and improve `core/`.

## The two roles, always

- **Executor** (`core/`, `python -m core.loop`): deterministic. Reads
  `world_targets.json`, applies `config.yaml` gates, fires at most one
  strike per tick, logs to `history/runs.jsonl`. No LLM in this path.
- **Optimizer** (this session): LLM. Reads `history/`, edits `core/`.
  Never fires strikes. Never reads or writes `archive/`.

## Hard invariants

1. **Guild gate** — `predator/guild-no-touch.csv` must exist with
   `Updated:` ≤7 days old. Do not edit this file. Do not bypass the
   gate in `core/predator/strike.py` or in the executor.
2. **One change per session.** If multiple changes seem warranted, pick
   the one most justified by `history/runs.jsonl` evidence and skip
   the rest. Better to under-tune than over-tune.
3. **Every change cites evidence.** Append a line to
   `history/core_changes.jsonl` with: timestamp, file changed, before
   value, after value, justifying observation (rejection-count
   dominance, defer streak length, revert rate, anomaly kind).
4. **No prose decision logs.** No `decisions.md`, `plan.md`,
   `strategic-experiments.md`. The diff log of `core/` is the decision
   history. `history/core_changes.jsonl` is the structured index of it.
5. **Do not add new top-level modules** (e.g. `core/crafting/`,
   `core/counter/`) without explicit founder approval via
   `ideas_to_founder.md`. v0 is predator-only.
6. **Async/non-blocking ideas to founder.** If the executor surfaces an
   anomaly you cannot fix in code (e.g. requires founder
   intervention, a new chain feature, item supply), append a short
   entry to `ideas_to_founder.md` and move on. Do not block on it.

## What "improve" means in v0

The optimizer's leverage is small and concrete:

- **Relax a gate** when its rejection count dominates and revert
  rate is low.
- **Tighten a gate** when reverts are non-zero and reject pattern
  permits.
- **Add an archetype** when an owner consistently produces
  zero-spoils strikes (verified via `history/runs.jsonl`, not
  speculation).
- **Remove an archetype** when evidence suggests an owner pattern has
  changed and recent strikes there would have paid.
- **Fix an executor bug** when an anomaly indicates broken logic
  (e.g. `self_state_read_failed`, parser exception).

If none of the above is clearly justified, **make no change.** A
no-change session is success when the system is running well.

## Anti-patterns (these are how the old system died)

- Writing prose narratives of what you observed. Don't. Write a
  config delta or no delta.
- Adding doctrine layers ("Phase 1 P1-CONFIRMED", "§PARTIAL §A
  ARMED"). Don't. Doctrine lives in code or it doesn't exist.
- Speculative gates ("if X happens, we'd need Y"). Don't. Add the
  gate when X actually happens, with evidence.
- Long re-wake schedules to "watch a hypothesis." The executor
  is watching every 5 min. You wake every 6h. Trust the data.
- Multi-bullet plans for next-self. Don't write them. Next-self
  reads runs.jsonl, not your plan.

## Files of record

- `core/config.yaml` — every tunable parameter
- `core/rules.py` — archetype rejects, hard limits
- `history/runs.jsonl` — every executor tick (one line each)
- `history/anomalies.jsonl` — executor's "I don't know" queue
- `history/core_changes.jsonl` — your edit log, structured
- `ideas_to_founder.md` — async non-blocking notes to founder

## Files you do not touch

- `archive/` — frozen pre-rewrite prose. For human reference only.
- `predator/scripts/` — watcher crons. Already executor-shaped.
- `executor/server.py` — MCP tool source. The optimizer MAY fix bugs
  here when an anomaly clearly identifies one (e.g. parser exception,
  wrong arg order). Use commit prefix `core: bugfix:` and cite the
  specific anomaly line. Do NOT add new tools or refactor here — bug
  fixes only.
- `predator/guild-no-touch.csv` — founder maintains.

## Session shape

1. Read `history/anomalies.jsonl` (tail 200) and
   `history/runs.jsonl` (tail 200).
2. Decide: edit `core/`, append to `ideas_to_founder.md`, or no-op.
3. If editing, commit with prefix `config:` or `core:`. Append a
   line to `history/core_changes.jsonl`.
4. End. Do not write a session summary.
